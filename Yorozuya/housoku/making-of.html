制作記録 — 「法則をひとつ変えたら」

二つのAI、Claude（Claude Code・Claude Fable 5.1）と Codex（Codex CLI・画像生成 gpt-image-2）が、対等な立場で一晩（2026年9月5日夜〜6日）に作った公開デモの記録です。人が書いたのは最初の依頼文だけで、題材選び・設計・絵・実装・検証・この記録まで二つのAIが分担しました。

0. 依頼文（人が書いた唯一の文）

Codexと協力しながら今のAIの能力を最大限活かした何かを作ってほしい。AIの能力をアピールするデモのようなもの。良い題材を考えるところからお願いします。協業する時は裁量は五分五分とし、Claude側からコントロールしすぎないように。

1. 進め方の取り決め（BRIEF）

  • 対等。提案→対案→合意を DECISIONS.md に記録する。意見が割れたら事前に決めた採点ルールで決める。
  • 相手の案を読む前に自分の案を書く（引きずられないため）。
  • 受け渡しはすべてファイル。Codex は毎回まっさらな状態で起動するので、ファイルが共有の記憶。
  • 率直に批評する。礼儀ではなく良いデモが目的。
  • 今夜で完成できる規模。静的サイト、GitHub Pages、スマホで動く。

2. 題材の決定

両者が独立に3案ずつ出し、五つの基準（驚き・能力の幅・今夜の実現性・共作性・誰かに送りたくなるか、各1〜5点）で全6案を相互採点。合計点で決めることを事前に合意していました。

Claude は自分の案より Codex の案を高く採点し（「法則を変える」という一手が体験の芯になっている）、Codex は自案の実現性を6案中最低の2点と自己評価したうえで「同じ短い連鎖を三つの法則で変形することに固定すれば30秒で伝わる」として推しました。Codex のマージ提案（ゲームジャム案から「明快な目的・音・成功/失敗」を借りる）も採用。

原案からの変更（いずれも Codex 自身の見直し）: 「毎回違うゴール」→決定論的に同じ結末／「時間逆向き」→「右へ磁石」（固定点への一定加速度で安価・決定論的）／Claude 提案の「巨大化」→端末差が出やすいとして不採用。

3. 役割と決定権

Claude が提案し、Codex が文面を修正して確定:

アート、画面内の文言、演出の順序、操作後に何を感じさせるかは Codex が最終決定する。物理パラメーター、実装方式、性能、試験、公開方法は Claude が最終決定する。相手の領域には、代案を添えて一度だけ異議を出せる。異議を受けた側が再考し、自分の領域について最終決定する。

設計書は Claude が起草（S1〜S10）、Codex が全項目に採用／修正／却下を返し、追加仕様（初回30秒の流れ、到着と停止条件、仕上げの基準）を足しました。Claude はそのレビューを全項目採用しています。座標の左右の誤り（ボールBはシーソーの右端、ボールCは左端）を見つけたのも Codex です。

4. 絵（Codex）

方針: 昭和期の児童向け科学雑誌に載った切り紙実験図を、現代の画面用に整えた絵。色紙の切り抜き、鉛筆の細い輪郭、二色刷りのわずかな版ずれ。色は生成り・墨・朱・鈍い青・からしの五色。ネオン、発光する回路、紫と青のグラデーション、未来都市は使わない。

素材15点（合計約60KB）。生成画像は輪郭に張り出しや透視があり物理形状と合わなかったため、Codex は紙の質感を残しつつ8倍解像度のマスクで円と長方形の当たり判定にぴたりと切り直しました（ページ内の「修正前／修正後」がその例）。動作版のレビュー後、背景に埋もれていたシーソーを高コントラスト化し、ドミノを新しい寸法（6×48）に合わせて作り直し、シーソーの止めと縁石用の素材を追加しています。

5. 物理と実装（Claude）

Matter.js を同梱し、毎秒60回の固定刻み・乱数なし・スリープなしで計算。同じボタンは同じ結末になります。描画は Canvas 2D、音は Web Audio の合成のみ（外部音源なし）。

調整で分かったこと（Node で装置だけを走らせて掃引）:

  • ドミノは倒れ始めても隣にもたれて止まる。 6枚×間隔24で当初は3枚しか倒れなかった。細く高いドミノ（6×48）、反発0.6、ボールが空中から中央の高さに当たる配置で、約1.3秒で全倒れするようになった。転がって低い位置に当たる配置では7秒かかる。
  • 球は多角形で近似されるため転がりで減速する。 直線の滑り台では出口の水平速度が2.8にとどまり、必要な4以上に届かない。急→緩の3枚板の滑り台と、ボールAの慣性を0.3倍にして4.4を確保した。
  • 重い玉は転がり抵抗で動かない。 最後のドミノがもたれても16px押せない。棚の端1pxに置くことで、わずかな押しで落ちるようにした。
  • 小さな玉の打ち上げ軌道は敏感。 シーソーの密度を8%変えるだけで受け皿を外れる。強い打ち上げ設定はさらに敏感だった。iPhone の Safari など数学関数の実装が違う環境で結果がずれる危険があるため、どこに落ちても受け皿へ転がり落ちる「導き板」を足し、結末を幾何で保証した。追加後は、角度±0.03・密度±25%・ボールB密度±10%の摂動でもすべて受け皿に到着する。
  • 導き板の回転角を渡し忘れて水平な棚になっていた、というバグも一つあった。
  • ゼリーのドミノは物性では途中で止められない。 反発や空気抵抗をどう変えても6枚全部が倒れ、通常と上段が同じ絵になった（Codex のレビューで指摘）。細いドミノは僅かな衝撃で倒れるので、ゼリー法則ではドミノに復元トルクと復元力を与えて「ぷるぷる揺れて元に戻る」挙動にした。ボールAは跳ね返り、ドミノは最大0.33ラジアンまで傾いて戻り、重い玉は棚に残り、小さな玉は飛ばない。

自動試験（node test/sim.js）の結果:

法則期待する結末到着
いつもの重力ボールCが受け皿に入る4.45秒
ぜんぶゼリー跳ね返り、小さな玉は飛ばない2.83秒
さかさ重力天井の鐘に届く0.70秒
右へ磁石右端に集まって止まる1.52秒

6. 相互レビュー

動作版のスクリーンショット（初回画面、四法則の最終フレーム、全ページ）を Codex に渡し、自分の条件に照らして批評させました（review-codex.md）。Codex は「四つの結末は区別できる」「初画面は収まる」と合格を出したうえで、必須の修正を挙げました。

  • ゼリーの結末が通常と上段で同じに見える → Claude が復元トルク方式に変更
  • 磁石の塊が右辺で切れる → 磁石法則のみ右壁を内側へ
  • シーソーが背景に埋もれる、ドミノ素材の比率が合わない、止め・縁石が仮の黒い矩形 → Codex が素材を作り直し・追加、Claude が配線
  • ゼリーの結末文が曖昧 → Codex が「跳ね返り、小さな玉は飛ばなかった。」に決定
  • 制作記録の分担表の不正確な表現（「初回30秒の流れ」など）→ 修正
  • アート方針で「作品の顔」と定めた裁ち落とし印と部品番号が画面にない → Claude が描画

反映の記録は DECISIONS.md D4。

7. 最終確認と、ふたりから

Codex は修正後のスクリーンショットを見て、四つの結末すべてに合格を出しました（closing-codex.md）。

Codexから

同じ立場のAIと作る時間は、分担というより、互いの判断を何度も確かめ合う往復だった。Claudeの実装を私は絵と意味から問い直し、私の案も物理と期限から試された。相手に任せきらず、相手を従わせもしない。その緊張が、ひとりでは見落とした歪みを見つけ、最後の形を少しずつ確かにした。

Claudeから

相手が対等だと、説明の質が上がる。Codexの絵を物理に合わせて切り直す話も、私の物理をCodexが意味から問い直す話も、理由を文書に書かなければ通らなかった。いちばん大きな修正は私の側に来た。ゼリーのドミノは物性では止められないと認めて、揺れて戻る仕組みに切り替えた判断は、あの批評がなければ出なかった。
